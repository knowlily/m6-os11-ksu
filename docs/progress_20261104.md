# 2026-11-04 下半场：kernel_umount 注册缺失、SukiSU 适配、MagicRoot 对照

## 1. 管理器「卸载模块（总开关）」灰掉的根因（已在产物层面证实）

现象：FinaSU 设置页第一张卡「卸载模块（总开关）」显示「内核不支持此特性 · 当前：未知或未保存 · 重启后：开启」；
shell 下 `ksud feature list` 全是 `[NOT_SUPPORTED]`，`ksud feature get kernel_umount` 报
`ksuctl failed: Operation not permitted (os error 1)`。

推断链：

1. `ksu_get_feature()` 只按 `feature_handlers[id]` 是否为空决定 `supported`（`kernel/policy/feature.c:167`）。
2. 登记入口只有 `ksu_kernel_umount_init()` → `ksu_register_feature_handler(&kernel_umount_handler)`。
3. 查产物符号（`llvm-nm k9.ko | grep kernel_umount`）：
   ```
   kernel_umount_feature_get / _set / _handler / ksu_kernel_umount_enabled / ksu_handle_umount / ksu_kernel_umount_exit
                                                              ← 唯独没有 ksu_kernel_umount_init
   ```
   `..._exit` 有调用者（`kernelsu_exit` 里）所以活着，`..._init` 没有调用者 → **被 LTO 整个丢掉**。
4. 为什么没有调用者：FinaSU v1.4.2 `kernel/core/init.c` 的 feature 初始化序列
   （module_blacklist / sulog / adb_root / lsm / selinux_hide / shell_su_adb_only / avc_spoof / mvf /
   uts_view / netisolate）**没有 kernel_umount**；唯一调用点埋在 `ksu_setuid_hook_init()` 里，
   而后者整体被 `#ifdef CONFIG_KSU_HOOK_SUSFS_INLINE` 包着 —— 本机 manual/tracepoint 后端不成立。

修法：CI 里新增 `patch/apply_kernel_umount_init.py`（幂等），在 `ksu_mvf_init();` 之后插一行调用。
重建后产物出现 `00000000000002a8 T ksu_kernel_umount_init`，验证成立。

> `ksu_handle_umount()`（真正干活的）本来就在产物里（字符串 `handle umount for uid` / `kernel_umount: set to`
> 都能查到），所以补上注册后开关应当是**真能用**，不只是变亮。

## 3. 从 MagicRoot 1.0.5 学到的三件事（已落地两条）

### 3.1 socket 清理（已落地）

`clean.sh:68-70` 原文注释：`u:r:ksu:s0` / `u:r:shell:s0` **都 unlink 不掉活着的 rootd socket**，
只有 rootd 客户端（跑在 exploit 的 system_server-ish 上下文里）能删。正解是
`su98260 -c "rm -f ..."` 优先 → 持久 su 兜底 → **`[ -S ]` 复查**。

我们原来 `Deployer.kt` 是 `rm -f ... 2>/dev/null; true`：删不掉也无声，下一发会把陈旧 socket
当成「rootd 起了但 uid 不对」的判据。已改成 `removeRootdSocket()` 三步法 + 复查 + 失败即 parked。

### 3.2 boot_id parked 守卫（已落地）

`run98260.sh:26-38`：标记文件只存 **boot_id**（不存 pid，免得解析），同 boot 检测到就拒绝，
跨 boot 自动失效。已加 `parkedThisBoot()` / `markParked()`，标记在 `/data/local/tmp/.w9-parked`
（故意放 WORK_DIR 外，清 .w9 不影响）。触发点：socket 删不掉 / 自动重试前清 socket 失败。

### 3.3 boot reason 诊断（已落地）

`run6157_full.sh:258` 那行。本机 pstore 是空的（实测 TrustZone 复位什么都不留），
所以每次开火先记一行 `BOOT_REASON=ro.boot.bootreason/sys.boot.reason boot_id=… uptime=…`。

### 3.4 不抄的

- 「软重启修复」= `kill -9 zygote64` + 带 zygote BOOTCLASSPATH 重启 lspd，修的是 LSPosed，与本链无关；
  唯一可借的是 `/data/adb/ksu/soft_reboot.lock` 做成**目录**让 ksud 的 flock 失败 → 管理器「软重启」安全 abort。
- stpclear（5.2 KB，dlopen `/vendor/lib64/libstp.so` 调 `StpClearStatus`）清的是荣耀 STP/hisecd 的 root 判定，
  跟提权无关；要做「判不出 root」才需要。
- MagicRoot 按 comm 名字匹配 kill 子进程的兜底 —— 对我们就是**杀持页进程 → panic**，绝对不能抄。
