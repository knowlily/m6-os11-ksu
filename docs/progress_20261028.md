## 走到这一步踩的两个坑

### 坑 1：vermagic 双写 localversion

```
got  6.1.157-android14-11-g84ffa64b710b-android14-11-g84ffa64b710b
want 6.1.157-android14-11-g84ffa64b710b
```

`scripts/setlocalversion:150` 里 `res="${config_localversion}${LOCALVERSION}"` —— `.config` 的
`CONFIG_LOCALVERSION` 和环境变量 `LOCALVERSION` 是**拼接**关系。修法：`--set-str LOCALVERSION ""`，只留一处。

### 坑 2：`-d MODVERSIONS` 会把 vermagic 的 token 也一起去掉

为了得到「不带版本表」的产物，第一版直接 `-d MODVERSIONS`，结果 vermagic 少了 `modversions`：

```
设备内核(VERMAGIC_STRING): … SMP preempt mod_unload modversions aarch64
我们的产物:                … SMP preempt mod_unload            aarch64   ← 整串比对必拒
```

内核比对的是**整串**，`modversions` 由构建内核的 `CONFIG_MODVERSIONS` 决定。
作者的 ko 是 `… mod_unload modversions aarch64` 且 `__versions` size=0 —— 即**开着编、编完清空段**。
修法：保留 `CONFIG_MODVERSIONS=y`（还加了硬检查），编完用 `scripts/strip_versions.py` 把
`__versions` / `__version_ext*` 的 `sh_size` 原地置 0。

`tools/target.py vermagic` 也从「只比版本号首字段」改成**整串比对**，并在版本号相同、token 不同时单独提示 ——
这两个坑以后都会被 CI 在产出前拦住。
