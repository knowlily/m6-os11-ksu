# 2026-11-02 FinaSU 全链路打通（管理器「未安装」+ su_compat 双杀）

设备：BVL-AN16 / MagicOS 11 / `6.1.157-android14-11-g84ffa64b710b`
结果：模块 `Live`、管理器「工作中 · 越狱模式」、superuser 9、模块 3、传统 su 可用、收尾 `getenforce=Enforcing`。

## 1. 管理器「未安装」的真因：注入点落在 `return` 之后

`patch/apply_sc_inject.py` 的 `patch_init()` 原来把 `ksu_sp_hooks_init();` 插在
`kernelsu_init()` 的**右大括号前**，而 FinaSU 这个函数结尾是：

```c
#endif
#endif
    return 0;
}
```

⇒ 调用落在 `return 0;` **之后**，编译器视为死代码 ⇒ 我们注入的**所有 kprobe 从未注册**：

- `__arm64_sys_setresuid`（zygote 给管理器 setuid 时装 `[ksu_driver]` fd）
- `__arm64_sys_execve` / `bprm`（su 重定向、commit_creds）
- `commit_creds` 兜底

管理器（FinaSU / SukiSU 的 `manager/.../cpp/ksu.cc`）**不调 reboot 拿 fd**，只
`scan_driver_fd()` 扫 `/proc/self/fd` 找 `[ksu_driver]`；fd 只能由内核在
`ksu_handle_setresuid()` → `ksu_install_fd()` 里塞进去。钩子没注册 ⇒ 永远「未安装」。

**修**：插到**最后一个 `return` 之前**。验证方式：把 `init.c` 拷出来跑一遍 `patch_init()` 看落点。

排除过但**不是原因**的：ksud/uapi 版本、加冕参数下发、tracepoint vs manual hook、
`ksu_hook_backend_ready` 位（强制 true 无效）、reboot supercall（一直是通的）。

## 2. `su_compat` 显示「内核不支持此特性」

管理器判定「支持」= 内核注册了对应 feature handler。上游只有两条路注册
`ksu_sucompat_init()`：`CONFIG_KSU_HOOK_SUSFS_INLINE` 分支，或
`ksu_syscall_hook_manager_init()` 成功之后。本机 `sys_call_table` 只读 ⇒ 分发器永远装不上
⇒ handler 从来没注册 ⇒ `NOT_SUPPORTED`。

**修**：自己注册一个 su_compat handler（`ksu_register_feature_handler` + 自有开关
`ksu_sp_sucompat_on`），su 重定向 kprobe 读同一个开关 ⇒ 管理器里的开关是真的开关。

## 3. 三个编译/加载坑（都踩过一遍）

| 现象 | 原因 | 修 |
|---|---|---|
| `error: missing terminating '"'` | 注入块是 Python 三引号字符串，里面写 `\n` 被求值成真换行，C 字符串被劈成两行 | 文件里写 `\\n`（2 个反斜杠） |
| `ERROR: modpost: Section mismatches detected`<br>`ksu_sp_hooks_init (.text) -> ksu_register_feature_handler (.init.text)` | 上游 `ksu_sucompat_init` / `ksu_register_feature_handler` **都是 `__init`** | 注册函数标 `void __init`，并在 `kernelsu_init()` 里调用（`.init` 调 `.init` 合法）；同时去掉 `static` 以便跨文件 |
| `module load failed: errno=8`<br>`dmesg: unsupported RELA relocation: 311` | `__attribute__((weak))` 取函数地址 → `R_AARCH64_ADR_GOT_PAGE`(311)，**本机内核模块加载器不支持 GOT 重定位** | 不能对模块内符号用 weak；改成强引用直接调 |

**打包前自检（重要）**：扫 `.rela` 段，`type ∈ {311,312,313}` 必须为 0。
脚本片段见 `scripts/check_relocs.py`（本仓库 `patch/check_relocs.py`）。

## 5. 本机可观测性边界

- `dmesg`、`/proc/kallsyms`、`/sys/module/kernelsu/parameters/*` 对 shell **全部 `Permission denied`**
- 装载后 `kgo.sh` 的 fork/exec 会卡住（`dmesg` 那条），日志从那一刻断
- 可用判据：`/proc/modules`（refcount 0→1 = 管理器持 fd）、`ksud debug info`、管理器 UI
- `ksud feature list` 从非管理器 uid 跑会**全部** `NOT_SUPPORTED`（权限被拒的伪装），不能当判据
